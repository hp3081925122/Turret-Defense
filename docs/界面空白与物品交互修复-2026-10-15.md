# 界面空白与物品交互修复

2026-10-15。用户报告开发客户端底座界面上方大块空白，滚动到下方才见内容，物品栏无法交互。用户确认来自项目runClient，并明确选择本轮先修复和构建、暂不启动客户端。

## 已确认的原因

- 客户端日志在10:40:02和10:42:02记录：打开base_core.html时，DOMContentLoaded脚本访问不存在的overload元素，抛出`Cannot set property "disabled" of null`。核心页短暂读到上一底座页的type=base状态，进入错误分支；旧脚本先refresh后建立定时器，异常会阻止后续刷新恢复。
- 原布局把六面塔头、升级材料、安装说明、名单、机器槽和玩家背包放入同一个长滚动面板。用户截图能确认物品区域被推到下方；旧日志没有直接槽位绑定错误，不能据此认定点击失败一定来自服务端绑定或AUI引擎。
- 截图对应的客户端日志是10:38–10:42会话，早于之后的资源修改。源码与当前构建资源一致，不能证明旧会话热加载了新资源。

## 本轮修改

1. 服务端状态附带menuId，客户端仅向当前同ID菜单提供状态，避免核心、底座和帮助页之间串用旧数据。页面还按data-machine检查类型；先启动刷新定时器再尝试首次刷新，并保护可选控件访问。
2. 核心、底座采用900×620固定画板，通过AUI的scale=fit等比适配窗口，不再给物品操作叠加自行计算的缩放或点击坐标。
3. 标题、能量和简短状态固定。左侧管理信息独立滚动，右侧机器槽和玩家背包常驻。核心补给与战利品分两列，玩家背包位于其下；底座共享插件、缓存和背包纵向放置。物品区域没有滚动祖先。
4. 面板使用明确的不透明背景色。机器容器显式display:block，槽位网格单独布局；逻辑slot-size和可见尺寸均28，原有容器ID、槽号、过滤器和服务端能力不变。
5. 增加英文调试日志，记录新菜单ID、类型、槽数和位置；客户端切换菜单状态时记录接收ID与当前ID，便于区分旧状态和真实容器问题。

## 11:44录像后的鼠标根因与修正

录像确认新版固定布局和玩家物品悬停提示已显示，但点击仍无效。当前AUI 1.2.7依赖字节码给出直接调用链：

`InputEvent.MouseButton.Pre → AUI Client.mouseButton → Operation.onMouseDown/onMouseUp → MouseEvent.tiggerEvent → Document.interceptsMouseEventsAt → consumeNative → Pre.setCanceled(true)`。

底座与核心模板均声明 `aui-mouse-events=intercept`。真实槽位也属于DOM命中区域，故点击在进入 `AbstractContainerScreen.mouseClicked` 前已被消费。悬停提示由绘制/hover路径更新，仍可显示；这与录像症状一致。此前只查DOM布局和服务端菜单，未覆盖此原生输入入口，不能视为完成交互修复。

已从底座、核心两页移除此声明。AUI文档与字节码确认：不设置intercept时HTML事件仍派发，按钮脚本继续工作；原生槽位点击同时能进入Minecraft。AUI的 `ApricityContainerScreen.init` 把 `imageWidth/imageHeight` 设置为实际screen宽高，因此画板内的非槽位点击不会被原版误判为画板外丢物。帮助/详情页不含真实槽位，保留原拦截声明。
